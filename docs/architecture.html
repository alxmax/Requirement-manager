What it's for

A written contract the code is checked against

A long agent session forgets what was agreed. A fresh one re-implements it another way. Two agents on one repository make incompatible choices and nothing tells either. A longer prompt does not fix that; a contract on disk that every change is checked against does.

Understand code you inherited

init reads the code you already have and drafts one requirement per capability. Every file is then reachable from what it is for, and every capability lists the files that implement and test it.

gate --show AUTH-LOGIN-001

Documentation that cannot rot quietly

The requirement is the documentation. When its contract changes and the code behind it is not re-checked, the gate names the requirement and the exact files to look at.

RM018 DRIFT — re-check hello.py:1

Keep AI agents on the agreed path

Every session and every agent reads the same contract before it writes code. Two requirements that describe the same thing are ranked side by side before they turn into two implementations.

ask --dupes

Clarify intent before writing code

clarify lists what a requirement has not answered yet: vague words, numbers without units, a clause with no case, a missing failure path. Unclear specs surface as questions, not as bugs later.

clarify AUTH-LOGIN-001

Prove each promise with a test

A test tags the case it proves, # verifies: ID#CASE-2. Coverage is then measured per clause, not per line, and gate --risk names what is untested and what to do next.

gate --risk

Code shaped by capability

One requirement per capability keeps modules small and named for what they do: a shared bus defined once, features composed on top of it. An advisory design review points at long files and abstraction candidates; it never fails a build.

ask --design
How it works

Spec, tag, gate, map

Four parts and one rule: the requirement file is the source of truth. Membership is found by scanning the code, never kept by hand.

Write the spec

One .md file per capability: frontmatter for the machine, a description and numbered cases for people.

Tag the code

A comment declares the role: implements, tested-by, verifies.

Run the gate

Before every commit and in CI. It only reads, and it fails the build only on what is actually broken.

Read the map

One self-contained HTML file: open it with a double-click, no server and no install.

The gate

A person confirms; the gate enforces

Confirming a requirement is not a command but someone's answer: a person reads it and sets status: confirmed. From then on the gate holds the code to it.

draft

Drafted from code, unreviewed. Not enforced.

baseline

Describes what the code does today.

implemented

Built. Enforced like confirmed: it must have code.

confirmed

Intent validated by a person. Enforced as truth.

deprecated

Retired. Old tags still resolve.

Errors exit 1

  • A tag points at a requirement that does not exist
  • A confirmed or implemented requirement has no code behind it
  • A depends_on target is missing
  • Frontmatter that cannot be read

Warnings exit 0 · errors with --strict

  • Drift: a contract changed, its code was not re-checked
  • A tested-by file with no test in it
  • A case no verifies: tag reaches
Commands

Six verbs

The verb tells you whether a command can change a file: only init and sync write. Everything else is a flag of one of the six.

init

Set up requirements/ and draft one requirement per capability from the code you have. Never overwrites a file.

gate

The verdict. Do the code and the specs still agree? Report-only; the one command that fails a build.

sync

Rebuild everything derived: the drift baseline, the map, the findings. Also cuts a planned release.

clarify

The questions a requirement has not answered yet. Read-only.

ask

Every other question: search, duplicates, design review, a review plan.

mcp

The same commands as typed tools for an AI assistant. Read-only unless started with --allow-writes.

Start in two minutes

Install the plugin once. The first time you use it in a repository it copies scripts/reqmap.py and the reqmap_engine/ package into it — Python 3.9+, standard library only, nothing else to install. Then wire the gate into your pre-commit hook and CI.

/plugin marketplace add alxmax/requirement-manager
/plugin install requirement-manager@requirement-manager
$python scripts/reqmap.py init
